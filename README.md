# 葡萄酒窖 · 酒款台账与窖藏批次

葡萄酒窖业务系统：管理酒款台账（按产区分组）、窖藏批次（窖藏中→可售放行）、会员（等级与积分）与销售出窖（出窖扣库存、退窖回滚）。主色酒红，左侧竖排导航，酒款按产区分组折叠。

## 模块

- **酒款 wine**：编号唯一、在售/停售；按产区（国产/法国/智利/澳洲/其他）与类型（红/白/起泡/甜）分组管理。库存为「各可售批次可用瓶数」合计的镜像，只随放行/出窖/退窖联动，不能直接录入或修改；发现批次与库存不一致时可在台账执行「按批次校准库存」（`POST /api/wines/{id}/reconcile-stock`）。
- **窖藏批次 cellar_batch**：关联酒款，批次号唯一、瓶数>0；记录总瓶数 `bottle_count` 与已出窖瓶数 `sold_count`，可用瓶数 = 二者之差。状态机：`窖藏中 --放行--> 可售 --售完--> 已售罄`（退窖回补时 已售罄→可售），拒绝跳级与重复操作；`POST /api/cellar-batches/{id}/release` 放行后瓶数计入酒款库存。
- **会员 member**：手机号唯一、积分≥0；出窖关联会员自动累加积分（1元=1分，记录在单 `points_earned`）并按积分升级等级（普通/银卡/黑卡），退窖按本单积分精确回滚、等级随积分复核（散客无积分）。
- **销售出窖 sale_out**：仅「在售」且存在可售批次、可用瓶数充足的酒款可进入出窖选择；新建即按**入窖最早批次优先（FIFO，同日按批次 id）**扣减，跨批次自动拆行，每次实际扣减在 `sale_out_item.batch_id` 逐批留痕，批次扣完自动转「已售罄」，酒款库存同步扣减；`POST /api/sale-outs/{id}/refund` 退窖按原批次逐项回补、恢复批次状态与酒款库存并回滚积分（散客同样适用）。出窖/退窖/放行全程行级悲观锁 + 单事务 + 状态前置复查，任一明细不足或重复提交时整单回滚，不留半成功数据。

### 批次联动要点

- 可售资格：只有「可售」批次的可用瓶数进入销售可售量；窖藏中不计、已售罄为 0。
- FIFO 扣减：同一酒款多批次时从最早入窖批次开始扣，实际扣到哪些批次逐行展示在出窖单明细（可展开查看）。
- 退窖回补：严格按出窖明细的原批次、原数量逐项回补，已售罄批次回补后自动恢复可售。
- 一致性：放行/出窖/退窖前校验「酒款库存 = 各可售批次可用瓶数合计」，不一致给出可理解错误并保留可继续处理状态（台账校准入口恢复）。

## 启动

```bash
sh start.sh     # 启动 mysql / backend / frontend
sh stop.sh      # 停止
sh clean.sh     # 彻底清理（含匿名数据卷）
```
